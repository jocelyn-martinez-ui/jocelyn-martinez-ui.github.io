## Alternatives considered

These are assessed directions, not three finished visual prototypes.

| Direction | Benefit | Tradeoff / decision |
| --- | --- | --- |
| Expressive studio gallery | Large images, display type, strong graphic/art-direction emphasis | Can obscure interaction evidence. Keep expressive project art, but do not make it the only structure. |
| Neutral product laboratory | Compact screens, strict grids and detailed states | Underrepresents editorial/graphic work and can flatten project differences. Use record clarity inside ImHere. |
| Editorial practice with working evidence | Warm paper, clear hierarchy, distinctive project identities, role routes and real captures | Needs disciplined editing and honest evidence labels. This is the implemented direction. |

ImHere pairs quiet institutional blue with a warm context panel. A roster → inspector → decision sequence was selected over direct inline mutation: proposing and applying a change must be distinct. A modal would offer less room for request context and history.

Áurea retains its burgundy/ivory and Italiana/DM Sans identity. Two semantic columns allow direct comparison and independent replacement. A carousel would obscure equivalent rows; unlimited columns would increase horizontal complexity. At 320 px the cost is denser wrapping, so full perfume names appear above the compact selectors.

Recommended positioning: **Visual & UI Designer**, with implementation as an advantage. The strongest through-line is a distinctive visual system carried into an inspectable interaction. Computer Science supports that story; it does not substitute for design rationale or user evidence.

For research-heavy product roles, the main gap is evidence from actual people and constraints. For graphic roles, prioritize one complete production story and honest native-tool capability. For UI/web roles, add device/assistive-technology evidence and a maintainable component structure. This assessment does not predict interviews or hiring success.
